# بداية نظيفة للتسليم

بيانات العملاء والموظفين والأصناف والعمليات محفوظة في Firebase. رفع الكود إلى GitHub مستقل عن تنظيف هذه البيانات.

## أولًا: النسخة والمعاينة

من مجلد المشروع:

```powershell
npm run data:prepare
```

هذا الأمر يقرأ البيانات فقط، ويحفظ نسخة كاملة من مستندات Firestore مع أنواعها وتواريخها ومجموعاتها الفرعية. لا يحذف أو يعدّل Firebase.

النسخة والمراجعة في مجلد `alfanar-private-backups` بجانب مجلد المشروع، وليس داخله. يعرض الأمر اسم مشروع Firebase وأعداد المستندات المقترح حذفها وحفظها وما يحتاج مراجعة. يتوقف مسار الحذف إن وجد مجموعة غير معروفة أو حساب دخول غير مصنف. لا ترفع النسخة الاحتياطية إلى GitHub ولا ترسل محتواها في المحادثات.

## نطاق البداية الكاملة

- حذف الموظفين التجريبيين وجداولهم ويومياتهم وجلساتهم، والعملاء وفهارس أرقامهم.
- حذف الأصناف والأسعار ودفاتر الكوبونات وأرقامها وحركاتها والأرصدة والتوريدات والحركات والطلبات والمبيعات والمستحقات والتسديدات والشفتات والعدادات والروابط.
- حذف إعداد اليومية وأوقات الشفتات التجريبية؛ يمكن إدخالها من الإدارة مجددًا.
- الاحتفاظ بحسابات Firebase Authentication للإدارة وتشغيل المحل دون تعديلها، والأجهزة المصرّحة وإعدادات الأمان والوصول. هذه بيانات الدخول الأساسية. بعد مراجعة حساب الهاتف التجريبي والموافقة عليه، يمكن تحديد معرّفه وحده عبر خيار `--legacy-phone-user` أثناء المعاينة؛ لا يُختار أي حساب هاتف آخر بالاستنتاج.
- يبدأ رصيد كل صنف جديد من الصفر. يبقى حساب المخزون التلقائي جاهزًا للعمل، وتُدخل الأصناف والأرصدة الحقيقية قبل الاستخدام.
- المجموعة غير المعروفة تُراجع ولا تُحذف بالاستنتاج من اسمها.

## تنفيذ التنظيف بعد اعتماد المراجعة

يجب إيقاف جميع نسخ التطبيق وعدم استخدام أي جهاز أو نسخة منشورة طوال التنظيف. يحذف الأمر بيانات حقيقية من المشروع المحدد؛ لذلك لا يُشغّل قبل مراجعة النسخة والأعداد وعبارة الاعتماد الخاصة بها.

الأداة `npm run data:reset` تتطلب المسار الكامل لملف `backup.json` في خيار `--backup`، وعبارة المراجعة المطابقة في `--confirm`، وتأكيد توقف الخوادم بالخيار `--servers-stopped`. لا تنفّذ أي حذف دون هذه المتطلبات. تُراجع البيانات وحسابات الدخول مجددًا قبل التنفيذ، ويمنع التغيير المتزامن حذف مستند تعدّل بعد النسخة. حساب الهاتف لا يُحذف إلا إذا كان معرّفه وتفاصيله مطابقين للحساب المعتمد في النسخة. في حال انقطاع التنفيذ، يبقى سجل المراحل بجانب النسخة؛ لا تبدأ نسخة أخرى قبل مراجعة الحالة.

بعد الانتهاء، أعد تشغيل التطبيق لإفراغ الذاكرة المؤقتة والجلسات القديمة من المتصفحات، وأضف الموظفين والعملاء والأصناف والأسعار والأرصدة الحقيقية. لا تستخدم بيانات العرض كأرصدة افتتاحية.

## GitHub

ترفع ملفات التشغيل والمصدر، ومنها `src` و`public` و`scripts` وملفات الإعداد و`package-lock.json`. ملفات البيئة والمفاتيح و`node_modules` و`.next` والنسخ الاحتياطية مستثناة. راجع التغييرات قبل الحفظ والرفع. لا يتطلب تنظيف Firebase حذف مجلد المشروع أو إعادة إنشائه.
